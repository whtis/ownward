> 状态：设计稿，实现暂停。数据可得性已实测验证（见 §3），实施路线见 §6。

## 0. 设计立场（先想清楚再写代码）

散户亏钱的三大源头不是"信号不够"，而是：**无成文计划**（追涨杀跌全凭当下情绪）、
**仓位失控**（一把梭/越跌越补没有边界）、**不复盘**（同样的错犯十遍）。
所以这个系统的对手是这三件事，不是市场。定位：

- **纪律执行官 + 情报官，不是预测机**。只做三件事：盯（数据）、判（规则命中）、催（到条件提醒你按你自己定的计划行事）
- **决策永远是人**。通知里给依据 + 建议 + 你当初写的规则原文，绝不代下单——与 Ownward 三道人工审批门同一哲学
- **策略即配置**：策略本体是 `STRATEGY.md`，与其他 Markdown 提示和规则一样人可读可改，
  改文件即改策略。v1 给默认值，用一个月后每条都会被你改成自己的——**这就是"你自己的策略"的形成过程**
- LLM 不碰数字：所有信号判定是确定性规则（纯函数），LLM 只负责把"命中了什么规则 + 数据"写成人话，以及周报定性综述

## 1. 策略框架本体：三层仓位

这是给你的 v1 框架提案（比例是默认值，需你拍板）：

### 核心仓 Core（~70%）— 宽基定投，日历驱动
- 标的：宽基 ETF（美股 VOO/QQQ；是否配 A股/港股宽基待定）
- 纪律：固定日历定投（每月发薪后第一个交易日）× **估值调节系数**：
  标的 PE 处于历史低百分位 → 加倍；高百分位 → 减半或暂停（数据：`calc-index`/`valuation`）
- 提醒：定投日 L2 提醒（含当期建议金额和估值依据）；核心仓占比偏离目标 ±10% → 再平衡提醒
- 除再平衡外永不卖出

### 卫星仓 Satellite（~25%）— 个股趋势仓，信号驱动
- 标的：watchlist 里你研究过的个股；入场判据 = 现有 lb-analyze.py 的多周期框架（周线定方向 + 日线四指标共振）
- **论点卡制度**（本设计的核心新增）：入场前必须写一张论点卡——为什么买、目标价、止损价、
  论点失效条件。**不写卡，系统不追踪不提醒**。卡存 vault `investing/thesis/`
- 出场纪律：止损价触发 → L1 立即打扰（最高优先级）；失效条件触发 → 提醒重审论点；到目标价 → 提醒按计划止盈
- 仓位纪律：单票 ≤ 卫星仓 1/3；卫星仓总占比超限 → 提醒
- 期权墙作为个股"地形图"：OI 集中的 strike（call/put wall）标注为潜在阻力/支撑，叠加在技术位旁边做参考

### 战术仓 Tactical（0–10%）— 事件驱动，情报驱动
- 财报日历：持仓/watchlist 个股财报前 2 天 L2 提醒（决策窗口：持有过财报还是减仓）
- 期权墙/GEX 周报：每周对持仓个股算一次 gamma 分布（gamma 用 BS 从 IV 推），标注 gamma flip 点
- 明确边界：v1 期权数据只做情报，不做期权交易建议

## 2. 通知分级（复用 triage 的克制哲学）

| 级别 | 通道 | 触发 |
|---|---|---|
| L1 立即打扰 | 横幅+飞书 | 止损触发、持仓票盘中急跌超阈值、明天财报 |
| L2 当日提醒 | 常规通知 | 定投日、共振入场信号、论点失效、再平衡、财报倒计时 |
| L3 只入日报 | daily-digest / 周报 | 常规扫描结果、估值变化、期权墙快照 |

盘中监控只盯**持仓票**（不盯全 watchlist），美股时段（北京深夜）只放行 L1。

## 3. 数据可得性（2026-07-18 实测）

| 数据 | 来源 | 状态 | 用途 |
|---|---|---|---|
| 行情/K线/量/资金 | `longbridge quote/kline/capital` | ✅ 现有 lb-analyze.py 在用 | 技术面扫描 |
| 估值 PE/PB | `longbridge calc-index` / `valuation` | ✅ 可用（历史百分位需实现时验证） | 定投调节系数 |
| 期权链（strike/合约） | `longbridge option chain` | ✅ 免费 | 墙的骨架 |
| 期权 OI/IV | `longbridge option quote` | ❌ **no quote access**（US 期权行情需付费订阅） | 期权墙/GEX |
| ↳ 替代源 | CBOE/Yahoo 延迟数据；IBKR 延迟行情(ib_async marketDataType=3/4 + genericTick 101) | 实现时验证 | 同上 |
| 市场情绪 | `longbridge market-temp`（0-100） | ✅ | 极端值提示 |
| 财报日历 | `longbridge finance-calendar` | ✅ | 事件提醒 |
| 真实持仓 | IBKR NAS 后端 `/positions` | ✅ BullTap 在用 | 仓位偏离/止损监控（不手输） |

关键认知：**OI 每日只随 OCC 隔夜结算更新一次**——期权墙天然是 EOD 快照型情报，
延迟/免费数据完全够用，应放在收盘后扫描而非盘中。

## 4. Ownward 集成架构（沿用现有分层，不加新概念）

```
STRATEGY.md              策略配置（行为即配置；三层比例/标的/止损宽度/定投日历全在这）
src/strategy/            确定性规则引擎：纯函数，数据 → 规则命中 → 事件（LLM 不参与）
sources/stock.ts 扩展     任务矩阵：
  盘中(持仓票)            止损/急跌监控，开盘时段 5-15min 轮询
  每日收盘后              watchlist 技术面扫描 + 期权墙快照 → 事件进队列 → triage 分级
  每周日晚                策略周报 routine（仓位/偏离/论点卡状态/下周事件）→ 草稿人审（复用 routines.ts）
  每月定投日              定投提醒 + 再平衡检查
Action 集成              策略提醒生成 Action 卡；resolve 条件 = IBKR 持仓实际变化（确定性验证）或手动 dismiss
vault 落地               vault 的 investing/：论点卡 + 交易日志 + 周报归档
memory 层                复盘沉淀走 _candidates 人审合并（如"急跌时你总想清仓"这类行为模式观察）
```

## 5. 复盘闭环（长出"独有策略"的唯一路径）

系统记录三元组：**提醒了什么 → 你实际做了什么（IBKR 持仓对账）→ 结果如何**。
月度复盘 routine 汇总：哪些规则你总是不执行（该改规则还是改行为？）、
止损/止盈纪律执行率、论点卡胜率。这个反馈回路是散户最缺的东西——
你的"独有策略"不是设计出来的，是这个回路迭代出来的。
