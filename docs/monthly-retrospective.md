# 会议材料归档与月度复盘

## 需求

月度复盘既要覆盖本人的工作，也要覆盖同项目同事已经整理过的产品、运营和研发进展。
晨会、周会文档是主要素材，工作日志和任务记录用于补充细节。每份草稿都应能说明
它依据哪段日期、哪些人员、哪一版原始材料生成；网络拉取失败或材料不完整时，应明确提示。

## 工作流程

1. 按 Ownward 配置的时区计算取材日期。月报取上一自然月；默认月度触发点为
   目标月第一个周一前的周日，跨月的周日也按目标月计算。
2. 读取 `refRoutines` 指向的晨会、周会文档，按 `people` 指定的姓名筛选。
   `people` 留空时使用 owner 姓名；没有可用姓名时明确报告缺少人员配置。
3. 在工作 scope 的 vault 中保存原文和来源信息。内容相同的拉取复用同一版本，
   内容变化保留新版本，不覆盖已经用于历史草稿的原始依据。
4. 将目标月份的每日记录与周级背景分开标识。相交周中属于下个月的每日列不能混入月报；
   无法可靠解析的合并单元格要提示材料缺失，不能把错位列当作正确记录。
5. 草稿以会议材料为主线，按项目方向合写多人进展；工作日志先去掉文件清单、hash、
   失败尝试等技术噪声，再作为补充。素材超过限额时标明截断，不能静默漏掉月末。
6. 保存草稿使用的日期窗口与材料版本。审核和列表刷新只检查本地材料状态，
   不同步拉取飞书文档；远端修改只有在下次成功取材后才能被本地发现。
7. 草稿继续通过既有人工审核，再受控写入飞书对应位置。

## 失败与试运行

- 拉取失败、有已验证归档：使用归档并明确显示离线/旧材料和抓取时间。
- 拉取失败、无归档：明确指出缺失来源，草稿不得编造该来源的内容。
- 归档写入失败：明确报告，不得把未保存材料称为已归档。
- `generateDraft(id, { dryRun: true })` 只返回草稿，不写归档、occurrence、Action 或通知；
  仍会调用只读取材和模型生成，因此并非零网络/零模型费用。

## 配置

以 `examples/routines.json` 的 `project-monthly` 为起点，在本机 `data/routines.json`
添加职责。把示例文档地址、项目、人员与引用的 routine ID 换成实际值，再开启 `enabled`。
`window: "month"` 控制上一自然月的素材范围，`cadence: "monthly"` 控制定时触发。
`time` 与 `aheadMin` 仍使用已有的截止时间及提前生成语义。
`refRoutines` 中填写已有职责的 ID，其 `docUrl` 是素材来源；月报自己的 `docUrl` 是输出目标。
引用、人员和周期字段通过规则更新接口校验后才保存。

这项功能在生成草稿时归档所引用的会议材料，不是全量飞书文档同步服务。
不会清理 Runner journal、会话 payload 或历史聊天；也不会自行删除旧归档版本。

## 归档与追溯

原文位于 `<vault>/<scope>/meetings/<文档 URL 的 SHA-256>/<内容 SHA-256>.md`。
开启工作/私人分流时使用 `work` scope，未开启时没有中间这一层。每个来源目录的
`latest.json` 记录 `url`、`hash` 和 `fetchedAt`，供后续读取当前版本；相同内容复用归档，
旧版原文保留用于追溯。单份原文上限为 2 MiB，超过时明确报告。

草稿 occurrence 保存实际取材日期、覆盖人员、来源元数据与告警。审核弹窗的「取材依据」
展示这些信息，不通过详情接口返回整份会议原文。来源版本、规则或本地工作日志变化会触发
过期提示；远端文档尚未重新抓取的修改无法由本地检查发现。归档文件是原始取材快照，
请勿直接编辑内容寻址文件；手工修改会导致完整性校验失败。

## 验收

- 同一文档重复拉取内容不变时复用版本，内容变化可追溯旧版。
- 离线回退、没有旧版、坏文件、越界或符号链接路径均有确定结果。
- 原始文件和元数据写入不会阻塞 HTTP 主线程执行大规模同步扫描。
- 8 月复盘不含 9 月每日记录；跨年、月末、配置时区不同于系统时区均正确。
- 配置验证拒绝非法周期、空人员及无效来源引用，失败不部分保存。
- 草稿材料版本对应实际输入；后续本地材料更新能被审核发现，列表不联网。
- 试运行无持久化副作用，真实写入仍须人工审核。
